# Center Messenger

Отдельный runtime MAX: [границы контейнера, подготовка перехода и откат](docs/operations/max-container.md).
Общая история и PostgreSQL сохраняются; обычный API-деплой не обновляет MAX image.
Обслуживание: [read-only аудит и обычный онлайн-бэкап API/MAX/DB](docs/operations/full-backup-split.md).
Там же: разбор ошибок адресата/SQL и сравнение MAX до и после API-релиза,
без отправок, перезапусков и запросов к CRM (`scripts/max_runtime_diagnostics.py`).

Кабинет мессенджера для клиентов студии: единое окно с переписками,
командой, настройками подключений CRM и ботами MAX.

Защита действующего MAX: [контур, серверная проверка выпуска и порядок
обновления эталона](docs/operations/max-release-protection.md).
Эталон до перехода на MAX-контейнер — `c72bdbcf8932859b34b342393f1ef75ebd90240a`, схема
`0029_invitation_sections`. При первом выпуске серверный загрузчик однократно
устанавливает внешнюю защиту до сборки и замены API. После этого проверка
и эталон не обновляются из `main` автоматически; для них нужна отдельная установка.

Инструкция разработчику: [общий загрузчик и подключение новых каналов](app/backend/src/center_messenger/loader/README.md).
В ней описаны адаптеры телефонии, вложений и мессенджеров, очереди, сохранение
курсоров, пример без сети и проверки совместимости.

Последний этап: [расписание синхронизации и карточка из кэша](docs/releases/2026-10-27-sync-cadence-cache-first.md).
Дополнение: [чтение карточки без пересчёта переписки](docs/releases/2026-10-27-family-read.md).
Правило отправки: [значки статуса, автоматическая сверка и единственная ошибка](docs/releases/2026-10-29-quiet-send-feedback.md).
Настройки карточек: **Подключения → Мастер подключения → Загрузчик карточек клиентов**.
Поля предзаполнены, редактируются прямо на странице и применяются кнопкой сохранения.
Подробности: [состояние загрузчика и кэша](docs/operations/card-loader-status.md).

## Стек

- **API** — FastAPI (Python 3.12), точка входа `center_messenger.main:app`
- **БД** — PostgreSQL (на текущем VPS 17), миграции Alembic (`app/backend/migrations`)
- **Публикация** — Nginx как reverse proxy перед API (`infra/nginx`)
- **Запуск** — Docker Compose (`compose.yaml`), образ собирается из `Dockerfile`

## Правило переписки родителя и нескольких учеников

**Верное правило:** карточки каждого ученика сохраняются отдельно по его ID
AlfaCRM, а переписка с одним подтверждённым участником MAX и счётчик
сообщений без ответа существуют **в одном диалоге родителя**. Один входящий
вопрос не становится тремя обращениями, если журнал AlfaCRM связал его с
тремя детьми. В карточке диалога показываются все доказанно связанные дети;
действующий ученик не должен исчезать из-за архивной карточки другого.

Подтверждение для автоматического объединения — **одна исходная входящая
запись журнала MAX**, прямо содержащая несколько CRM ID учеников, плюс
совпадающий основной телефон в опубликованном справочнике AlfaCRM.
Совпадения телефона, имени, текста или времени по отдельности недостаточно.
Массовые исходящие и вручную привязанные оператором диалоги не объединяются.
Исходные ID журнала и карточки всех учеников сохраняются. Существующие копии
такой записи объединяются фоновой сверкой без повторной загрузки старой
истории из браузера AlfaCRM. Новые сообщения объединяются только пока
опубликованный справочник подтверждает исходную связь и телефон; сохранённые
источники не удаляются. Если входящий вопрос не называет ребёнка, оператор
уточняет контекст, прежде чем подтверждать конкретное занятие.

## Сборка и запуск

```bash
docker build --platform linux/amd64 -t center-messenger:local .
docker compose config --quiet
docker compose up -d --wait db
docker compose run --rm migrate
docker compose up -d --wait api
curl --fail --silent --show-error http://127.0.0.1:8100/health/ready
```

Ожидается `{"status":"ready"}`. Процесс без применённых миграций или с ролью
владельца БД возвращает 503.

## Проверки

```bash
python3 -m pip install -r requirements-test.txt
python3 -m compileall -q app/backend/src app/backend/migrations scripts
PYTHONPATH=app/backend/src python3 -m unittest discover -s tests -p 'test_*.py' -v
npm ci --ignore-scripts
npm test
docker run --rm --entrypoint alembic <image> -c /app/alembic.ini history
```

Для проверок импорта/чтения сообщений задайте `CM_TEST_DATABASE_URL` с адресом
отдельной тестовой PostgreSQL. Набор создаёт случайную схему и применяет в ней
все миграции. Без этого адреса интеграционные проверки явно пропускаются.
Для тестов интерфейса требуется Node.js 24; Node не требуется рабочему серверу.

Проверка настоящей прокрутки в Chromium на вымышленных данных:

```sh
npx playwright install --with-deps chromium
npm run test:scroll
npm run test:progress
```

Проверяются 201 сообщение, нативное колесо мыши, сохранение позиции и отсутствие
пропусков при старых/новых обновлениях. Для уже установленного Chromium можно
задать `CM_TEST_CHROMIUM_EXECUTABLE`; дополнительные аргументы передаются JSON-массивом
в `CM_TEST_CHROMIUM_ARGS`. Доступ к рабочим сообщениям и отправка клиентам не нужны.
Проверка `test:progress` открывает весь кабинет с вымышленным API: ошибка 503,
зависший запрос с отменой по таймауту, восстановление статуса и прекращение
опроса при выходе из подключений. Проверка блокировок в `test_history_snapshot.py`
требует обычной PostgreSQL; для PGlite она явно пропускается.

## Репозиторий и развёртывание

**Актуальный репозиторий:** `rastudiocmit-bot/ramessenger`, ветка `main`.
**Целевой VPS:** `83.222.25.109`, действующее приложение на `https://rachat.ru/`.

GitHub Actions не используем; публикации помечаются `[skip ci]`.
Единственный владелец деплоя — `ramessenger-local-build.service` с существующим
серверным таймером и внешней защитой MAX. Сборка, обязательные проверки,
резервный дамп, readiness и откат выполняются на VPS. Обычный выпуск меняет
только API; MAX закреплён отдельным image. Подробности — в
[правилах серверного доступа](docs/operations/multi-agent-server-access.md) и
[защите выпуска](docs/operations/max-release-protection.md).

Не изменять работающие Nginx/PM2 и сайт `rastudio.org`; не выполнять
`docker compose down --volumes` на сервере.
