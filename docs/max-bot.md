# MAX в Center Messenger · 0.8.0

В кабинете предусмотрены два самостоятельных способа подключения MAX. У них
разные настройки, секреты, API и жизненный цикл. Подключение или отключение
одного способа не меняет второй.

| Канал | Настройка | Транспорт | Что поступает в историю |
| --- | --- | --- | --- |
| MAX Bot API | API-токен бота | Официальный Bot API и отдельный webhook Center Messenger | События бота после его включения в кабинете |
| MAX через AlfaCRM | Веб-вход пользователя AlfaCRM и временный код из письма при запросе | Серверный изолированный Chromium открывает штатные страницы AlfaCRM MAX | Входящие и исходящие из страниц истории AlfaCRM |

Ключи AlfaCRM v2api и X-APP-KEY не являются токенами MAX-бота. Веб-сессия
AlfaCRM не передаётся боту, не меняет MAX Bot API и не подключает тот же токен
второй раз.

## Штатный MAX через AlfaCRM

Этот канал работает через внутренние страницы CRM: `/company/{branch}/max/receive`,
`/sent` и штатную форму `/bulk`. Пароль используется только для входа и не
сохраняется. Запомненные cookies и браузерное состояние шифруются ключом
подключений и хранятся отдельно от настроек MAX-ботов. После входа AlfaCRM может
попросить одноразовый код из письма. Код вводится в кабинете, а не записывается
в логи или базу.

Сервер использует отдельный временный headless Chromium для входа, чтения истории
и отправки. Сессия продолжает работать, когда вкладки AlfaCRM закрыты. При
отключении канала зашифрованная сессия удаляется; уже импортированная история
остаётся в кабинете. Если CRM завершит сессию, кабинет покажет необходимость
подключить её снова.

### Установка и подключение

1. В разделе «Подключения» сначала настройте API AlfaCRM и загрузите список
   филиалов. Для этой интеграции по-прежнему нужны действующие API-настройки
   AlfaCRM.
2. В отдельной карточке «MAX через AlfaCRM» введите почту и пароль пользователя,
   которому доступна штатная переписка MAX. Не вводите сюда API-ключи.
3. Если CRM запросит подтверждение, введите код из письма и нажмите
   «Подтвердить вход».
4. После статуса «Подключено» сервер поставит первую синхронизацию в очередь.
   Последнюю историю можно обновить кнопкой «Синхронизировать историю».
5. В разделе «Сообщения» выберите «MAX через AlfaCRM» или «Все каналы MAX».

До подключения владельцем рабочего логина и проверки на реальном аккаунте
нельзя считать вход/выдачу кода, получение всех нужных страниц и фактическую
отправку подтверждёнными для конкретной конфигурации AlfaCRM. В тестовой среде
используются только вымышленные данные. Пароль/код не запрашиваются и не хранятся
в репозитории.

### История, объединение и неотвеченные

При каждой синхронизации сервер проверяет первую страницу входящих и исходящих
для каждого доступного филиала и постепенно проходит предыдущие страницы.
Записи сохраняются в PostgreSQL, а повторы AlfaCRM сводятся по ID строки и
получателю. Отдельные страницы филиалов проецируются в одну переписку, если
карточки детей в опубликованном справочнике AlfaCRM связаны с одним `contact_id`.
В рамках одной записи MAX несколько карточек этого родителя тоже дают одно
сообщение. Пока справочник не связал карточку с контактом, CRM может временно
показывать её отдельно.

Непрочитанность каждый раз рассчитывается из сохранённых сообщений, а не из
порядка загрузки страниц. Диалог непрочитан, если последнее входящее сообщение
клиента новее последнего подтверждённого ответа человека. Ответ из штатного
MAX AlfaCRM учитывается так же, как ответ из этого кабинета.

Автоматические, системные, неизвестные и неудачные исходящие сообщения ответом
не считаются. Имя само по себе не доказывает, что сообщение написал человек:
AlfaCRM может отправить триггер от имени сотрудника. Человеческий автор
подтверждается по данным пользователя в строке CRM. При одинаковой отображаемой
минуте сравнивается числовой ID строки только внутри одного филиала; если CRM не
даёт надёжного порядка, система оставляет диалог непрочитанным, пока синхронизация
не найдёт более точную временную метку или подтверждённую последовательность.
Открытие диалога не помечает его прочитанным.

История ограничивается данными, доступными в штатных таблицах AlfaCRM и в
периоде, который вернула CRM. Фоновая синхронизация обрабатывает по одной
предыдущей странице за проход, поэтому полная начальная загрузка большой истории
может занять несколько циклов. Она продолжается, даже если браузер пользователя
закрыт.

### Отправка через штатную форму

1. Для выбранного диалога сервер берёт филиал и карточку из последнего входящего
   сообщения.
2. Он открывает штатную форму MAX, читает текущий CSRF-токен и проверяет
   совпадение филиала, карточки и MAX ID получателя.
3. Отправляется только непустой текст, один раз и только после успешной
   проверки формы. Отправка не зависит от API v2api и не использует токен MAX-бота.
4. Успешный ответ CRM сохраняется в локальной истории. Если соединение оборвалось
   после начала POST и результат нельзя достоверно определить, запись отмечается
   как «Результат неизвестен», автоматического повтора нет. Сначала проверьте
   исходящие в AlfaCRM.

Если AlfaCRM не возвращает форму или MAX ID получателя, сервис останавливается
без отправки. В карточке семьи с несколькими детьми получателем считается MAX
контакт, а не конкретный ребёнок.

## MAX Bot API

В карточке «MAX · боты» добавляется токен отдельного бота MAX для бизнеса.
Сервис проверяет `/me` и webhooks, затем при явном включении создаёт webhook
Center Messenger. Новые сообщения принимает отдельный endpoint; токен хранится
зашифрованным. Это подключение не входит в веб-сессию AlfaCRM, не использует
пароль/код пользователя и не меняет настройки штатного MAX AlfaCRM.

Бот получает только события после включения; предыдущую переписку из AlfaCRM
сам по себе не импортирует. В этой версии MAX Bot API отправляет текст; доставка
или прочтение подтверждаются только отдельными статусами платформы. Повтор
неопределённой отправки автоматически не выполняется.

## Изоляция и эксплуатация

Миграция `0007_alfa_max_browser` удаляет переключатель совместного режима из
`max_settings` и добавляет таблицу отдельной веб-сессии AlfaCRM MAX с FORCE RLS.
Очередь синхронизации содержит только ID и lease. Секретные cookies хранятся в
AEAD-шифротексте, привязанном к организации и подключению. Пароль и код не
пишутся в базу, журналы приложения, аналитические события или Git.

Chromium и его системные библиотеки входят в проверяемый Docker-образ. Веб-формы
проверяют CSRF, доступ владельца/администратора и workspace. Браузерный клиент
разрешает только HTTPS на домене AlfaCRM и официальном CDN; произвольные
редиректы блокируются.

Другие MAX/Telegram-аккаунты, Telegram-боты, ВК, подписки и Яндекс Cloud —
отдельные будущие каналы. Ни один из них не подразумевается этой настройкой.
