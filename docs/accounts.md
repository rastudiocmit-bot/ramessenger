# Личный кабинет закрытого пилота — 0.2.0

## Что работает

Первый владелец создаёт аккаунт по одноразовому коду, который находится только
на сервере. В той же транзакции создаётся его организация. Повторная настройка
блокируется базой, в том числе при двух одновременных запросах.

Владелец и администратор могут переименовать центр, посмотреть сотрудников,
создать приглашение и отозвать доступ. Ссылка приглашения действует 48 часов,
используется один раз и привязана к почте. Отправка ссылки сотруднику выполняется
вручную. В журнал HTTP не попадает токен из URL: он передаётся во фрагменте `#`,
удаляется из адресной строки интерфейсом и отправляется API в JSON.

Существующий аккаунт принимает приглашение после входа с соответствующей почтой.
Это позволяет одному человеку работать в нескольких центрах с разными ролями.
Новое приглашение не повышает роль уже активного участника. Отозванное участие
можно восстановить новым явным приглашением. При удалении сотрудника его
неиспользованные приглашения отзываются.

| Роль | Организация | Сотрудники | Свой пароль и сессии |
| --- | --- | --- | --- |
| Владелец | Просмотр и название | Приглашения и отзыв доступа, кроме владельца | Да |
| Администратор | Просмотр и название | Управление тремя младшими ролями | Да |
| Руководитель филиала | Просмотр | Нет | Да |
| Оператор | Просмотр | Нет | Да |
| Наблюдатель | Просмотр | Нет | Да |

Участие в центре проверяется заново на сервере при каждой операции. Идентификатор
организации из URL или заголовка сам по себе не даёт доступа. Ограничения филиалов
и каналов будут реализованы вместе с соответствующими модулями. Сейчас назначение
роли руководителя филиала не открывает несуществующие API чатов.

Кабинет адаптируется к телефону. Реальные браузерные проверки используют Chromium,
PostgreSQL и вымышленные аккаунты. Наличие мобильного кабинета не означает, что
мобильный чат, PWA или приложения магазинов уже реализованы.

## Пароли и сессии

Пароль — от 15 до 128 символов; допускается удобная длинная фраза. В базе хранится
Argon2id-хеш с отдельной солью (64 MiB, три прохода). Одновременно выполняются не
более двух операций хеширования на процесс. Секреты не возвращаются в ошибках
валидации и не записываются в аудит.

Cookie сессии имеет HttpOnly, Secure, SameSite=Lax и префикс `__Host-` на HTTPS.
В базе хранится только SHA-256 токена. Токен сессии не сохраняется в localStorage.
Сессия живёт максимум 12 часов; после 60 минут без обращений к API нужен повторный
вход. Изменение пароля и выход на всех устройствах немедленно завершают сессии.
После потери доступа к центру аккаунт может управлять собственными сессиями.

Для изменений проверяются точный Origin, JSON, CSRF-токен и размер тела до 8 KiB.
Попытки входа ограничиваются по хешам адреса и почты в PostgreSQL. Ответ на
неверный пароль одинаков для существующей и неизвестной почты.

Только при loopback-порте API и Nginx, который заменяет `X-Real-IP`, допустима
настройка `CM_TRUST_PROXY_IP=true`. Схема пилота соответствует этому условию.
Для другого размещения нужно проверить границу доверенного прокси.

## Что ещё отсутствует

Это закрытый пилот: нет открытой регистрации центров, отправки и подтверждения
email, самостоятельного восстановления пароля и MFA. Почта приглашения не
считается подтверждённой: `email_verified=false`. Не запускать платную публичную
регистрацию до реализации соответствующих процессов. Пока нет проверки владельца
почтового ящика, ссылку нужно передавать сотруднику по согласованному каналу.

В 0.3.0 добавлены [настройки АльфаCRM и кэш филиалов](alfa-connection.md).
Коннекторы MAX/Telegram/ВК, импорт клиентов, сообщения, биллинг и Яндекс Cloud остаются
следующими этапами. Кабинет не показывает вымышленные диалоги и подключения.

Для первичной настройки: открыть корень HTTPS-домена, взять локальный код из
`.secrets/owner_bootstrap_token`, заполнить имя, почту, название центра и пароль.
Код и пароль не отправлять в чат. После успешной настройки код больше не даёт
создавать владельца. Ручное обнуление `auth_bootstrap` не является восстановлением
пароля и не должно выполняться на рабочей базе.
