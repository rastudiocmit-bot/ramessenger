# Проверка исправлений MAX через AlfaCRM — 26.10.2026

Проверена реализация из PR #53 относительно ТЗ о правах операторов,
достоверных статусах и автоматическом восстановлении общей браузерной сессии.
Проверка обнаружила дополнительные ошибки; они исправлены в дополнении.
Причина конкретного пользовательского события не восстановлена по серверному
журналу. Найденные дефекты не выдаются за доказанную причину того события.

## Найденные и исправленные несогласования

| Проблема | Исправление и проверка |
|---|---|
| Подготовка нового входа удаляла текущие cookies, очередь и настройки до проверки нового пароля | Для существующего подключения подготовка не меняет состояние. Замена выполняется после результата входа под общей блокировкой и с проверкой CRM-настроек. Неверный пароль оставляет прежнюю сессию и историю работоспособными. |
| После успешного логина сбой проверочного чтения возвращал старые cookies | Новое состояние сохраняется до проверки, с приостановленной отправкой. Следующая попытка сначала проверяет эти cookies, не отправляет пароль повторно. Частичный результат браузера также сохраняется для проверки. |
| Подтверждение кодом при сетевой ошибке могло восприниматься как неверный код | Сетевые ошибки отделены от отказа кода. Промежуточные cookies сохраняются, результат проверяется чтением. Обнаруженная форма одноразового кода переводит подключение в ожидание подтверждения без нового запроса пароля. |
| Продление блокировки и запись подозрения могли перезаписать конкурирующие изменения | Все контрольные операции сериализуются блокировкой строки организации. Продление также проверяет владельца, поколение и исходный шифротекст в условном UPDATE; обновляется только срок аренды. |
| Проверка поколения не учитывала изменение настроек внешней CRM | Сравниваются также ID текущего подключения CRM, её origin и версия настроек. Устаревшие результаты и ошибки отклоняются. Диагностические чтения не используют старый origin. |
| Неудача освобождения блокировки могла заменить подтверждённый результат отправки исключением | Ошибка БД при очистке оставляет освобождение сроку аренды. Подтверждённая отправка остаётся принятой. Ошибка экспорта cookies в самом браузере после подтверждения тоже не превращается в неизвестный результат. |
| Чтение шаблонов в обработчике истории запускало второй браузер и теряло обновлённые cookies | Шаблоны читаются в отдельной странице существующего контекста. Обновлённое состояние попадает в тот же сохраняемый снимок; родительская страница и контекст не закрываются. |
| Запрет одного филиала мог мешать проверке всей авторизации | HTTP 401, 403, 429 и временные ошибки различаются. При 403 проверяется другой доступный филиал; это не вызывает новый вход само по себе. |
| Успешное сохранение cookies стирало предупреждение о неполной истории | Коды history_* сохраняются независимо от восстановления авторизации. Курсоры и сообщения не перезапускаются ради сессии. |
| Отказ от автологина не сохранялся при повторном открытии формы | Явная настройка отделена от отсутствия старых данных. Отключённый автологин остаётся отключённым, сервер не отправляет пароль. |
| Временная ошибка опроса останавливала обновление статуса | После сетевой ошибки/503 опрос возобновляется; набираемый пароль и локальная настройка не стираются. |
| Причина изменения состояния заменялась следующей операцией | Сохраняются последние 10 безопасных событий с временем, источником, причиной и поколениями. В настройках есть раскрываемая история; секреты в события не включаются. |

## Соответствие исходному ТЗ

| Пункты | Результат проверки |
|---|---|
| 1–2. Разделение сессии сотрудника, API CRM и браузерного MAX | Добавление и принятие приглашения другим пользователем проверено операциями Accounts с отдельной сессией. Общая сессия CRM и вход владельца не меняются. Историческая причина конкретного разлогинивания остаётся неподтверждённой. |
| 3–4. Единые права и отзыв доступа | Общая политика роли/раздела действует в API и отправителе. Оператор проходит очередь без административной роли. Отзыв доступа отменяет его отправку, не интеграцию. |
| 5. Правдивые статусы | Отменённая отправка имеет предупреждение, не галочку успеха. Принято, неизвестно и отменено не смешиваются. Подтверждение приёма не выдаётся за доставку. |
| 6–7. Определение выхода и подтверждающая проверка | Скрытые парольные поля, в том числе скрытые Bootstrap-окна, не означают выход. Форма пароля, ожидание кода, 401/403/429 и сетевые ошибки различаются. До нового входа проверяется текущая сессия. |
| 8–9. Защита старых результатов и сохранение состояния | Есть общая возобновляемая блокировка, проверка поколения, шифротекста и CRM-настроек. Старый запрос не сохраняет cookies поверх нового входа. Потеря ответа проверяется до повтора пароля. |
| 10. Внешняя ошибка не завершает вход сотрудника | Неверный пароль CRM возвращает 422; это не локальный 401. Регистрация оператора проверена отдельно. |
| 11–12. Понятное состояние и диагностика | Показываются проверка, восстановление, ожидание кода и необходимость данных. Есть история безопасных событий и продолжение опроса после временного сбоя. |
| 13. Старые отменённые отправки | Автоматической повторной рассылки нет. Неизвестные отправки не повторяются, принятые не повторяются при ошибке сохранения состояния. |
| 14–15. Проверки и установка | Добавлены регрессии БД, интерфейса и Chromium. Тестовые формы и диалоги синтетические. Установка подтверждается отдельно по публичной версии и готовности сервиса. |
| 16. Серверный автологин | Восстановление выполняется общей серверной очередью без открытого окна. Начинается с проверки актуальных cookies. |
| 17. Хранение данных | Пароль находится внутри существующего AEAD-конверта, не в открытых метаданных, браузерном storage или API. Старому подключению без пароля нужен однократный ввод через настройки. |
| 18. Дополнительное подтверждение | Код вводится администратором; обход подтверждения не реализуется. Промежуточное состояние сохраняется, повторные письма/пароли автоматически не запрашиваются. |
| 19. Ограничение попыток | Проверены задержки 1, 5, затем не менее 15 минут; неправильные данные останавливают попытки. Явное отключение автологина соблюдается. |
| 20. Ручное отключение | Удаляет зашифрованные данные и очередь, увеличивает поколение. Поздний результат не включает подключение; безопасная история событий сохраняется. |
| 21. Очередь сообщений | Ожидающие отправки сохраняются и проверяют актуальные права. Принятые/неизвестные результаты не повторяются вслепую. |
| 22–23. Визуализация и критерии | Проверяются компьютер и телефон, настройка автологина, сохранение ввода при обновлении, восстановление опроса после 503 и отсутствие секретов в отчётах. |

## Границы доказательств

- БД-проверки выполняются в изолированной тестовой БД, браузерные — в настоящем
  Chromium с перехваченными синтетическими страницами. Реальным клиентам
  сообщения не отправляются, рабочая CRM намеренно не разлогинивается.
- Два теста, требующие отдельного нативного PostgreSQL для параллельных сценариев,
  пропускаются в текущей среде. Последовательные проверки владельцев аренды,
  поколений, отзывов и устаревших результатов выполняются.
- Фактическое требование одноразового кода и срок внешней сессии задаёт AlfaCRM.
  Автовход требует ранее сохранённого пароля и не обходит дополнительное
  подтверждение. Это предусмотренное ограничение, а не автоматический сброс.
