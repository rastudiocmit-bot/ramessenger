# Grok во всех ИИ-агентах

Задача: подключение отдельного API xAI в «ИИ-шлюзах» и выбор Grok для
голосового ввода, обработки текста, задач и телефонных разговоров.
Ключ вводится владельцем/администратором в интерфейсе; в командах его нет.

## Область выпуска

Обновляются API и закреплённый `telephony-worker` через прежний deploy owner.
MAX image, MAX runtime contract, Compose, зависимости и версия схемы
`0032_telephony_ai` сохраняются. Телефонный контракт меняется с
`novofon-family-care-v1` на `novofon-family-care-grok-v2`.

Отдельно проверенные изменения защищённых файлов:

- `telephony_agent.py`: создание клиента Grok и выбор именно этого клиента
  для проверки сохранённого телефонного профиля.
- `telephony_ai_worker.py`: выбор Grok для фонового описания и включение
  шифротекста его ключа в снимок подключений незавершённого задания.
- Телефонные тестовые модули, включая PostgreSQL: проверка выбора клиента, отдельного ASR,
  расхода, инструкций и смены ключа во время обработки.
- `run_max_compatibility.py`: добавлены тесты Grok и общих ИИ-шлюзов.

В policy также закреплены новые `ai_grok.py`, изменённые общие
`ai_voice.py` / `ai_gateways.py`, новый `test_ai_grok.py` и тестовые
зависимости `test_ai_voice.py`, `test_ai_yandex.py`, `test_ai_mimo.py`.
Это явная смена проверенного телефонного контура, а не обычный API-only выпуск.
Остальные ранее защищённые файлы должны совпадать с прежней policy.

## Установка

Прежняя установленная policy:
`c1de322ceb65199f4cf4dac0bec7291567cef2c52f7f98a109fb4a85b72705b7`.
Последнее подтверждённое приложение: `a67b5715c2fa356174c10e835c18906c6daf08d9`;
MAX: `center-messenger:max-a7a48c058942`;
телефония: `center-messenger:telephony-2f70515e74f9`.

После публикации точного проверенного SHA используется существующий
`scripts/prepare_telephony_update.py` с его точными SHA, image tags и
старым/новым SHA-256 policy. Подготовка устанавливает проверенное поколение
guard и план телефонного обновления; сама контейнеры не переключает.
Затем запускается `systemctl start --no-block ramessenger-local-build.service`.
Точные значения для опубликованного коммита выдаются отдельно: файл не может
содержать собственный commit SHA.

Под одним deploy lock выполняются сборка, обязательные MAX offline/database
проверки без пропусков, проверенный DB dump, обновление телефонного worker и
API, readiness и фиксация нового pin. До успеха тестов приложение не меняется.
При сбое используется штатный откат; БД из дампа автоматически не восстанавливается.
Никакой второй runner, удаление блокировок или перезапуск MAX не требуется.

Успех подтверждают `TELEPHONY WORKER UPDATE COMPLETE; MAX UNCHANGED`,
`LOCAL DEPLOYED <точный SHA>` и `healthy` у API/телефонии.
Один запуск команды или `TELEPHONY UPDATE PREPARED` не подтверждает установку.

## Приёмка

1. В «Подключения → ИИ-шлюзы» видна карточка «Grok · xAI».
2. Сохранение ключа не вызывает API xAI; поле очищается, отображается только
   окончание ключа. Замена/удаление сбрасывает проверку этого шлюза.
3. «Проверить подключение» выполняет короткий платный текстовый запрос;
   ошибки ключа, баланса, модели и лимита показываются без тела ответа.
4. Grok выбирается во всех трёх общих назначениях и у телефонного агента.
   Сохранение телефонного агента не запускает переработку звонков.
5. Фоновое описание использует Grok, выбранный ASR сохраняется. Учитывается
   расход, сохраняются правила телефонного агента и защита от повтора
   неопределённого платного запроса.
6. Ввод ключа, подключение и реальный платный запрос требуют проверки с
   пользовательским аккаунтом; локальные тесты используют синтетические ответы.

## Результаты локальной проверки

374 UI-теста; 152 теста провайдеров, телефонного агента/обработчика,
обновления runtime и release guard; Chromium на 1440/390/320 px:
зашифрованные реквизиты имитируются, доступны все четыре назначения,
проверки запускаются явно, горизонтального переполнения нет.

Полный MAX offline suite в этой среде не прошёл как обязательный gate:
11 native-process тестов требуют согласованного PID namespace `/proc`,
ещё один тест требует установленного Chromium ожидаемой версии. Его
нельзя считать пройденным по локальному UI-браузеру. PostgreSQL suite
локально не запускался: Docker/изолированная БД отсутствуют. Оба обязательных
контейнерных suite без пропусков запускает штатный deploy owner на VPS;
это условие перед переключением приложения сохранено.
