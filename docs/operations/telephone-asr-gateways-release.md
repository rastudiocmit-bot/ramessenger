# Шлюзы распознавания телефонных разговоров

В «AI-агенты → Телефонные разговоры → Настройки → Шлюз распознавания речи»
доступны Yandex Cloud, Grok · xAI, MiMo и MiMo Token Plan. Распознаватель
сохраняется отдельно от модели краткого описания и от голосового ввода чата.
Ключи и прокси берутся из существующих настроек «ИИ-шлюзы».

Grok распознаёт записи через официальный REST `POST https://api.x.ai/v1/stt`,
модель `grok-voice-transcribe-2.0`, язык `ru`. Клиент отправляет WAV с одним
каналом PCM16/16kHz, до 25 секунд, а файл размещает последним полем multipart.
Сохраняются слова-паразиты, автоматическая нормализация чисел выключена.
Роли каналов остаются неподтверждёнными. Внешний URL записи провайдеру не
передаётся. Распознавание использует тот же сохранённый маршрут прокси Grok,
что и обработка текста; при ошибке нет повтора или перехода на прямой маршрут.

Резервирование бюджета и результат каждого фрагмента проходят через прежний
журнал платных операций. Оценка REST STT — $0.10/час на канал, с округлением
длительности вверх до секунды и техническим курсом 90 ₽/$; это оценка бюджета,
а не выписка провайдера. Нулевой PCM не отправляется. Незавершённый ответ
требует проверки; автоматическая повторная платная отправка не выполняется.
Ночной график, интервал между архивными звонками и снимки уже созданных
заданий сохраняются. Сохранение агента не включает обработку автоматически.

Каталог текстовых моделей xAI не подтверждает доступ конкретного ключа к STT.
Реальная обработка использует выбранный аккаунт и его права. Для MiMo русский
по-прежнему отправляется как `auto`; качество нужно проверять на реальной
записи. DeepSeek не включён в распознаватели: официальный API описывает
текст/изображения, а не входное аудио.

не меняются. Прокси допускает дополнительно только точный POST `/v1/stt`
при явном производственном флаге; диагностика по умолчанию остаётся GET-only.

Локально: 155 тестов шлюзов/телефонного воркера; 46 тестов guard и runtime;
384 проверки интерфейса; Chromium на ширинах 1440, 390 и 320 пикселей
проверяет четыре пункта, сохранение Grok ASR, независимую модель описания
и остальные назначения агентов. Все внешние клиенты в тестах синтетические;
реальное платное распознавание не запускалось.

Обязательные offline и database MAX gate в контейнерах остаются этапами VPS.
Локальные unit-тесты не заменяют их. По `AGENTS.md` последующие обновления
защиты требуют явной серверной установки. Для точного итогового SHA main
используется `scripts/prepare_telephony_update.py` с обеими policy и текущими
образами API, телефона и MAX, затем единственный владелец выкладки
`ramessenger-local-build.service`. Он проверяет совместимость, делает дамп,
обновляет телефон/API и проверяет readiness; при сбое действует штатный откат.

Приёмка: `LOCAL DEPLOYED <SHA>`, API и телефон healthy, `/health/ready` ready,
образ MAX прежний. В настройках телефонного агента появляются четыре шлюза;
сохранённый выбор остаётся после обновления страницы. Первое распознавание
через Grok запускается явным запросом обработки или ранее включённым
пользователем расписанием, с действующим месячным бюджетом.
