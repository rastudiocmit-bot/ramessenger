# Ошибка адресной сверки журнала AlfaCRM

Консоль WinSCP показывает отдельное окно ошибки, когда серверная команда
возвращает ненулевой код. Сообщение `History audit unavailable: AlfaBrowserError`
из старой версии означает, что не удалось завершить чтение журнала внутренним
браузером. Оно не позволяет отличить запуск Chromium, сеть, истечение сессии,
тайм-аут, HTTP-ошибку и неизвестный формат страницы.

Обновлённая команда сохраняет полный отчёт покрытия базы и добавляет блок
`source_verification`, в том числе при сбое чтения:

```bash
docker exec center-messenger-api-1 /opt/venv/bin/python -m center_messenger.history_audit --verify-source --branch 4 --direction sent --progress
```

`--progress` выводит страницы в stderr, сохраняя JSON в stdout. При ошибке stderr
содержит краткую причину, а JSON — поля:

- `status: failed` — сверка источника не завершена;
- `error_code` — `browser_unavailable`, `crm_unavailable`, `reauth_required`,
  `invalid_response`, `network` или другой разрешённый код;
- `stage` — запуск драйвера/браузера, создание контекста, переход на страницу,
  проверка сессии, разбор страницы или получение состояния браузера;
- `cause` — `timeout`, `browser_closed` либо `browser_error`, когда категория
  известна из типа исключения;
- `http_status` — HTTP-статус ответа, когда он получен;
- `failed_page` — номер проблемной страницы, начиная с 1;
- `pages_checked`, `observed_rows` — объём успешно обработанных данных до сбоя.

При незавершённой сверке не выводятся итоговые `missing_in_database` и
`saved_not_observed`: частичный проход не является доказательством отсутствия
всех ещё не прочитанных записей. Успешная сверка имеет `status: complete` и
возвращает конкретные исходные ID, повторы и расхождения.

Коды выхода сохранены:

- `0`: проверка завершена и история подтверждена;
- `2`: отчёт получен, но есть незавершённость/расхождения;
- `1`: проверку не удалось выполнить из-за технической ошибки.

Поэтому окно ошибки WinSCP само по себе не означает аварийное закрытие
мессенджера. Нужно читать код и причину в отчёте. Адресная сверка только читает
источник и базу; она не меняет сообщения, курсоры загрузчика или сохранённую
браузерную сессию. Обновление диагностики не устраняет неизвестную ошибку
рабочего сервера автоматически — новый отчёт нужен для её точного определения.

В диагностике используются только разрешённые коды, этапы и числовые поля.
Текст исключений Playwright, HTML, URL с параметрами, cookies и данные клиентов
в отчёт не передаются.
