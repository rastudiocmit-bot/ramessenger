# Проверка формы подключения Новофона

Проверка выполнена локально для изменения с вкладкой «Подключения → Новофон».
Ключ аккаунта не предоставлялся, живые запросы к Новофону и звонки не выполнялись.

| Проверка | Результат |
| --- | --- |
| Общие DOM-тесты интерфейса, включая новую вкладку | 259 пройдено |
| Диагностика, сервис настроек и HTTP/CSRF | 35 пройдено; 2 PostgreSQL-теста не запущены |
| Точный парный план, image ID, прерывание и откат | 30 пройдено |
| API rollback, включая порядок восстановления схемы | 7 пройдено |
| Внешняя защита выпуска и согласованность policy | 27 пройдено |
| Python compileall, JS syntax, git diff --check | Пройдены |

Проверены шифрование и привязка ключа к центру/назначению, права
администратора, пустое поле при повторном сохранении, версия настроек,
удаление во время проверки, отсутствие контактов/секрета в отчёте,
сетевые ошибки, повторное нажатие, смена организации и отложенное
подтверждение отключения. Форма не вложена в другую форму; новый скрипт
подключён перед app.js. Использованы существующие стили карточек и адаптивная
одноколоночная раскладка.

## Обязательные серверные проверки

Полный pinned MAX gate **локально не пройден**: из 193 выбранных offline
проверок 181 выполнилась успешно, 11 пропущены из-за ограничений Linux/PID
окружения и 1 заблокирована отсутствующим Chromium. Набор не изменялся,
чтобы скрыть эти ограничения. Установить Chromium и запустить браузер в
текущем окружении не удалось; визуальная проверка страницы не подтверждена.

PostgreSQL/Docker здесь не доступны для нужной проверки. До изменения
производственной БД штатный guard запускает offline-набор без пропусков
в готовом образе с Chromium, затем 73 проверки на отдельном PostgreSQL
того же image ID, что производственная БД, в отдельной внутренней сети.
В этот набор добавлены RLS и повторный upgrade/downgrade Новофона.
Производственные секреты, volume, CRM и клиентские отправки не используются.
Ошибка или пропуск обязательной проверки блокируют выпуск.

Публикация кода не означает установку на сайте. После серверного выпуска
нужны проверка образов/readiness и свежей истории MAX, затем визуальная
проверка вкладки на компьютере и телефоне и диагностика с введённым на
сайте API-ключом. Только это подтвердит подключение конкретного аккаунта.
