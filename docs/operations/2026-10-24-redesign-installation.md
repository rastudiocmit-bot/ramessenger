# Подготовка оформления к установке

Основа — пользовательский архив `razvivaysya-redesign (2).zip`. Этот выпуск
подключает его оформление к действующему кабинету и добавляет явный выбор темы.
Ролевые HTML из `reference/` остаются демонстрационными макетами: их сводка,
мобильное нижнее меню и имитация отправки не подменяют рабочий интерфейс и API.

## Подключение

`index.html` загружает `appearance.js?v=1.0` до таблиц стилей, затем исходный
`app.css?v=0.8.33` и слой `redesign.css?v=1.1`. Для изменённого рендера аватара
используется `chat.js?v=0.8.17`. Исходный `app.css` не редактируется. Каталог
`web/` уже целиком отдаётся через `/assets/`; серверный список файлов не нужен.
Логотипы из архива сохранены как отдельные ресурсы для дальнейшей вёрстки.

## Тема

В сообщениях открыть шестерёнку «Настройки мессенджера» → «Тема оформления».
Доступны «Светлая» и «Тёмная». По умолчанию используется светлая; настройка
операционной системы не выбирает и не переключает тему кабинета.

Выбор сохраняется в `localStorage` под ключом `cm-theme` для данного браузера
и адреса сайта, применяется до загрузки CSS и обновляется в соседних вкладках.
Переход между разделами или организациями не сбрасывает оформление. Это личная
настройка браузера, а не настройка организации и не синхронизация между устройствами.
Если браузер запрещает сохранение, тема действует на открытой странице,
а под переключателем отображается пояснение. Настройки звука хранятся отдельно.

Тёмная тема оформляет меню, формы, диалоги, справочник и область переписки,
а не только пузыри сообщений. Оформление не меняет права доступа по ролям.

## Счётчик: актуальная инструкция

Текущий `renderList` уже получает `unread_count`. Отдельного `unread-badge`
в строке списка нет, поэтому искать и переносить такой элемент не требуется.
Внутри кнопки `contact-avatar` остаются `avatar-letter` с инициалом клиента
и `avatar-open` с действием открытия карточки. При положительном счётчике
добавляется `span.avatar-count` в правом верхнем углу аватара.

Формула прежняя: `Math.min(unread_count, 99)`. Для программы чтения с экрана
кнопка сообщает полное число. При нуле бейдж не создаётся. Бейдж не перехватывает
клики, поэтому кнопка по-прежнему открывает карточку CRM. Синие цвета, круглая
форма и размер бейджа сохранены из макета; перерасчёта непрочитанных на клиенте нет.

## Прокрутка

В надстройке используются реальные прокручиваемые контейнеры:
`.chat-list-scroll`, `.chat-stream`, `.directory-list-panel`, `.directory-detail`
и `.content`. Скрывается только полоса, свойства `overflow` не заменяются.
Колесо мыши и подгрузка старой истории продолжают работать.

## Проверка перед установкой

```sh
npm test
npm run test:appearance
npm run test:scroll
npm run test:progress
python3 -m compileall -q app/backend/src
docker compose config --quiet
```

Браузерные проверки используют Playwright и синтетические API-ответы. Для среды
со своим Chromium доступны `CM_TEST_CHROMIUM_EXECUTABLE` и
`CM_TEST_CHROMIUM_ARGS` (JSON-массив аргументов). Необязательный
`CM_APPEARANCE_SCREENSHOT_DIR` задаёт каталог снимков тестового кабинета.

Изменения готовятся в отдельной ветке. После проверки diff и слияния используется
штатный `ramessenger-local-build.service`; ручная замена файлов в контейнере не нужна.
После обновления кабинета проверить обе темы, настройки, клики по аватару,
счётчики и прокрутку списка/истории на компьютере и телефоне.

В этом выпуске нет изменений миграций, хранения сообщений, синхронизатора,
API, Dockerfile или контроллера установки. Процесс восстановления истории
сохраняет существующие позиции. Откат кода выполняется штатным развёртыванием
предыдущего образа; откат рабочей базы для оформления не требуется.
