# Диагностика незавершённого переноса CRM-адресата

`scripts/diagnose_max_relink.py` выполняется внутри действующего `max-worker`.
Принимает старый Customer ID и новый ID **как кандидата для проверки**, а не
как команду изменить получателя. Открывает только read-only DB-снимок, без
браузера, запросов к CRM, повторов сообщений и изменения aliases/очередей.

```bash
docker exec -i center-messenger-max-worker-1 /opt/venv/bin/python - --old-customer OLD_ID --new-customer NEW_ID < scripts/diagnose_max_relink.py
```

Показывает Customer ID, филиал, status, contact ID и хэш основного телефона
из текущей публикации. Старые aliases выводятся без телефона и с отдельными
признаками совпадения версии CRM-настроек/подключения. Исходные входящие,
включая скрытые копии, ограничены последними 100 строками; поле truncated
означает, что отсутствие пары в выборке нельзя считать отсутствием в БД.

Для устаревшей строки ищется сохранённая новая проекция с тем же source branch
и record ID. Полный список observed customers сохраняется: массовая строка
не превращается в доказательство одного адресата. Без полного source observation
пара не реконструируется. Дополнительные проверки вызывают настоящие read-only
функции установленного MAX: точность ID/времени/peer, текущие CRM-контакты,
совпадение основных телефонов и доказанность истории прежнего диалога.

Результат содержит `failed_checks` и текущий результат `reply_target` по уже
сохранённым связям. Он не вызывает `native_relink.prove` и не снимает
`crm_recipient_stale`. Совпадение одного номера или выбранный для сравнения
новый ID не разрешают перенос. Для исправления нужны достаточные source/peer
свидетельства и отдельная проверка защищённого контура MAX.

Если есть только старая неудачная команда, а текущая форма адресата уже
проверяется успешно, это не доказательство повторной доставки. Повторы старых
команд автоматически не выполняются.
