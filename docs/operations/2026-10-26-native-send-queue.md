# Очередь отправки MAX через AlfaCRM — 26.10.2026

Повторная проверка по снимку с несколькими исходящими сообщениями с часами
выявила воспроизводимую ошибку после первого переноса отправки в очередь.
Сам снимок не позволяет проверить состояние рабочей CRM или подтвердить
первоначальную причину выхода из неё.

## Ошибка очереди

При занятом браузере, изменившемся снимке сессии или проверке авторизации
отправитель освобождал задание, записывая `lease_until='-infinity'`.
Следующий выбор задания делал `SELECT message_jobs.*`. Psycopg пытался
преобразовать специальное значение PostgreSQL в Python datetime и выдавал:

```
psycopg.DataError: timestamp too small (before year 1): '-infinity'
```

Ошибка возникала до получения задания и его обновления. Перезапуск службы
не исправлял сохранённое значение; старейшее такое задание могло снова мешать
разбору очереди. Это воспроизведено тестом реальной очереди в изолированной БД.

## Исправление

- Выборка задания получает только используемые идентификаторы и типы, без
  преобразования дат аренды. Условия срока аренды и порядка остаются в SQL.
  Поэтому выбираются и ранее отложенные задания с `-infinity`; при получении
  они получают обычную новую аренду.
- Новые переносы используют конечную дату, как остальные пути отправителя.
- `browser_busy` и `settings_changed` сохраняют свои причины ожидания.
  Они больше не маскируются как проверка авторизации.
- Реальное ожидание авторизации сохраняет `session_check_pending`.

Миграция, очистка истории, удаление сообщений и повтор принятых/неизвестных
отправок не требуются. Настоящая дополнительная авторизация AlfaCRM, если она
нужна, остаётся отдельным условием продолжения.

## Проверка

Python: 444 теста, 442 успешно, 2 пропущены из-за требования отдельного
нативного PostgreSQL для параллельных сценариев. Новые регрессии проверяют:

1. Занятую историю аренду браузера, правильный текст ожидания и успешную
   однократную отправку после освобождения.
2. Существующее задание с `-infinity`, его получение и отправку один раз.
3. Изменившийся снимок сессии без ложного сообщения об авторизации.
4. Сохранение причины ожидания при настоящей проверке сессии.

Браузер и интерфейс этим дополнением не меняются. Реальным клиентам тестовые
сообщения не отправлялись.

## Перед восстановлением рабочей очереди

На пользовательском снимке несколько одинаковых исходящих сообщений с часами.
Это могут быть отдельные команды повторного нажатия. Исправленный отправитель
обработает каждую сохранённую команду: совпадение текста само по себе не даёт
права отменять намеренную отправку. Перед установкой требуется решить,
сохранять ли все такие команды или оставить одну, отменив лишние. Рабочая
очередь из этой среды недоступна, её содержимое и количество не выдумываются.
