# Единый список чатов: выпуск 24 октября 2026 года

Автоматические сообщения могли поднимать старое обращение вверх, поскольку
счётчик исключал автоматизацию, а дата и превью выбирались из любых событий.
Теперь все эти показатели рассчитываются по единому серверному правилу.

## Поведение

- Один список без вкладок «Все», «Нужен ответ», «Лиды» и отдельной очереди
  в меню. «Чаты» остаются первым и стартовым разделом. Явные фильтры и их
  сброс находятся в профиле; выбор фильтра не расширяет права.
- Сначала диалоги с неотвеченными, затем остальные. В каждом состоянии
  дата приоритета убывает с точностью до микросекунд, при равенстве — стабильный ID.
- Счётчик, превью, дата и ожидание происходят из одного множества неотвеченных.
  Новое входящее сбрасывает начало ожидания на своё исходное время, сохраняя
  предыдущие обращения в счётчике. Загрузка старой истории не создаёт дату «сегодня».
- Автоматизация и неизвестный исходящий автор не закрывают обращения и не
  меняют свежесть. При отсутствии человеческого общения строка остаётся
  внизу без даты и счётчика. Полная история, включая автоматизацию, сохраняется.
- Для ручного ответа подтверждение канала обязательно. Команда хранит
  исходную границу увиденных входящих; позднее подтверждение и эхо AlfaCRM
  не расширяют её на новые сообщения. Неоднозначное эхо во время отправки
  сохраняется отдельно до подтверждения и сверки.
- «Обработано», включая свайп, подтверждает только показанный снимок.
  Новое сообщение во время операции остаётся неотвеченным. Непроверяемая
  граница отклоняется; старому интерфейсу предлагается обновить страницу.
- Страница старой истории, частичная дельта и уведомления не продвигают
  границу просмотра. Независимая последовательность снимка защищает строку
  от позднего устаревшего ответа API даже при одинаковой ревизии диалога.
- Текст шаблона сам по себе не доказывает автоматизацию. Явная рассылка от
  имени сотрудника остаётся автоматической; ручная отправка шаблона — человеческой.
  В payload сохраняется основание классификации. Независимые номера строк
  входящего и исходящего журналов не доказывают порядок при равной дате.
- Сохраняются идентичность AlfaCRM, связи семьи, подтверждённые зеркала,
  самостоятельные одинаковые сообщения и записи источника. Обработка
  следует за подтверждённой копией; редактирование MAX не стирает ручную отметку.

## Данные и установка

Миграции схемы нет: head остаётся `0012_member_sections`. Существующий
защищённый установщик, резервная копия и восстановление образа сохраняются.
Версии ресурсов: chat.js 0.10.0, cabinet.js 2.4, app.js 0.11.0.

Производные `needs_reply` и дата приоритета пересчитываются серверным
потоком пакетами по 40 диалогов. Контрольная точка и версия находятся
в `connections.capabilities.chat_queue_projection`. Незавершённая работа
возобновляется; позиции загрузчика, аренда и `history_cursor.client_repair`
не сбрасываются. До завершения пакетов список использует тот же расчёт
на чтении; после завершения использует сохранённый порядок и рассчитывает
подробности только загруженных строк.

Ручные подтверждения сохраняются в производных `handled_receipt` конкретных
сообщений, чтобы объединение семьи не обработало неувиденные сообщения
соседнего диалога. Исходный текст, дата и ID при этом не меняются.

Обычная установка на существующем VPS:

```sh
systemctl start ramessenger-local-build.service
docker inspect --format '{{.Config.Image}}' center-messenger-api-1
```

Образ должен соответствовать SHA выпуска в main. После установки обновить
открытые окна с полной перезагрузкой ресурсов. Дополнительный запуск
«Синхронизировать историю» для нового расчёта не нужен.

Для намеренного повторного пересчёта, в том числе после отката на версию
со старыми правилами и последующего возвращения к этому выпуску:

```sh
docker exec center-messenger-api-1 /opt/venv/bin/python -m center_messenger.chat_queue --rebuild
```

Команда сбрасывает только маркер производного расчёта; сервер повторит
пакеты. Её не следует добавлять в обычный опрос интерфейса.
Полнота исходной истории проверяется отдельно:

```sh
docker exec center-messenger-api-1 /opt/venv/bin/python -m center_messenger.history_audit
```

В отчёт добавлен `chat_queue_projection`. Его `complete` не заменяет
`history_complete` и `totals_verified`: прежние пропуски и неопознанные строки
не скрываются и не удаляются. Исторический аудит пользователя не является
проверкой текущего состояния сервера.

## Проверка

- 122 серверных теста на PostgreSQL 16.15, без пропусков. Включены реальные
  параллельные транзакции записи входящего и обработки, RLS роли cm_app,
  позднее подтверждение и эхо, сбой ответа, ручные отметки, зеркала,
  повторное чтение источника, пересчёт и 105 диалогов с переходом через страницы.
- 63 интерфейсных теста: старые режимы, фильтры профиля, точность времени,
  сохранение выбора и черновиков, последовательность страниц, свайп,
  частичные изменения и поздний снимок с устаревшим счётчиком.
- Chromium 153: пять ролей и ограниченный доступ, светлая и тёмная темы,
  мобильная ширина 390 px, настройки, карточка семьи, подключение и состояния
  загрузчика. Проверка истории из 201 сообщения: смещение после дельты
  0,375 px, после колесика 0 px; ошибок JavaScript нет.
- Python compileall, node --check, git diff --check.

Синтетическая нагрузка, 3 741 диалог и 52 374 сообщения; порог запроса 2 500 мс:

максимальный пакет 586.31 мс при параллельной браузерной проверке.

Паузы рабочего потока между пакетами в эти измерения не входят.
Это проверочная среда, а не измерение производительности VPS.

Доступа к рабочей базе и активной сессии AlfaCRM в этой среде нет.
Фактический установленный образ, реальный клиент по его AlfaCRM ID и свежая
полнота исходной истории требуют проверки после установки на VPS.
