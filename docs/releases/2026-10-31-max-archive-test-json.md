# Исправление SQL подготовки приёмочных тестов MAX

Серверный выпуск `6aaee799` остановился до замены рабочих контейнеров:
все три новые PostgreSQL-приёмки получили `A value is required for bind
parameter 'true'`. `sqlalchemy.text()` разбирал двоеточие внутри JSON-литерала
как начало именованного SQL-параметра.

Обе вставки JSON в общей тестовой подготовке переведены на
`CAST(:payload AS jsonb)` с отдельно переданным `json.dumps` значением.
Дополнительная offline-проверка вызывает эту же подготовку и компилирует
каждый её запрос реальным PostgreSQL-диалектом SQLAlchemy с фактическими
параметрами. До исправления она воспроизводит серверную ошибку.

Приёмочные сценарии и их утверждения сохранены. Код приложения, Compose,
зависимости и схема PostgreSQL не изменены. Policy обновляет только хэши
двух проверенных тестовых файлов; остальные защищённые хэши сохраняются.
Ожидаемые обязательные наборы на VPS: 161 offline и 71 isolated DB-проверка,
без пропусков. Реальный PostgreSQL локально не запускался; окончательный
результат этих приёмок и установки подтверждается журналом VPS.
Локально прошли 163 выбранные проверки правил, тестовой подготовки, защиты,
обновления worker, аудита и резервных копий. Полный контейнерный offline-набор
также требует Chromium и соответствующего Linux PID namespace; он остаётся
обязательным серверным этапом.

Выпуск заменяет только ещё подготовленный план предыдущего SHA через штатный
`max_runtime_deploy.py --update-worker`. Новая policy устанавливается явно,
затем выпуск выполняет существующий `ramessenger-local-build.service`.
Проверки совместимости и резервная копия остаются обязательными.
