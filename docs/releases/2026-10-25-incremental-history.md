# Однократная история, новые сообщения и отображение ФИО

## Поведение

Первичный обход MAX-журналов выполняется один раз для всех клиентов, включая
архивных. Каждое направление каждого филиала имеет независимую сохранённую
позицию. После завершения читаются новые записи с начала журналов; при большом
числе новых записей отдельная позиция догружает их до пересечения с уже
сохранёнными ID. Входящие архивных клиентов и ответы, написанные прямо в AlfaCRM,
продолжают поступать. Обновление не удаляет сообщения и не обнуляет позиции.

Повторное чтение подтверждённого исходного ID не меняет текст, время, автора,
вложения или версию сообщения. Сопоставление ожидающих локальных отправок с их
подтверждением из CRM сохраняется. Новая связь по ID может прикрепить сохранённую
переписку к клиенту, не переписывая её содержание.

Завершённые старые обходы переводятся в состояние «история сохранена». Их
предыдущий результат не сбрасывается по шестичасовому таймеру. Прежние числовые
расхождения между строками CRM и уникальными ID не запускают повторный архивный
обход: повторяющиеся исходные ID учитываются отдельно. Явно обнаруженные
несохранённые ID остаются проблемой, пока не подтверждено сохранение.

Для новых первичных обходов сохраняются постраничные подтверждения вне регулярно
опрашиваемого состояния. Подтверждение полноты требует непрерывных страниц,
согласованных счётчиков и отсутствия повторяющихся исходных ID. Прежний импорт
без таких подтверждений не получает вымышленную отметку полной проверки.

## Сверка действующих клиентов

Отдельный серверный worker проверяет лёгкие сведения о действующих клиентах раз
в 6 часов после успешного завершения. Используется официальный запрос
`POST /v2api/{branch}/customer/index` с `is_study=1`, `removed=0`:
[документация AlfaCRM](https://alfacrm.pro/usefull/integrations/integration/api).
Учитывается реально полученное число карточек, а не предполагаемый размер
страницы. Повторы страниц не публикуются как успешный результат.

Известные архивные карточки не входят в периодическую выборку. Если ранее
действующий ID исчез из неё, его статус уточняется отдельно один раз. Новые
активные ID добавляются без объединения по имени или телефону. Связи между
филиалами переиспользуются только при подтверждённом членстве в исходных данных.
Изменение имени родителя помечается для проверки без переноса семьи по имени.

После перехода штатного MAX-подключения на эту политику автоматический полный
импорт справочника прекращается. Уже запущенный или явно запрошенный полный
импорт разрешено закончить. Полные финансовые карточки продолжают использовать
отдельный кэш: обновление ожидающих ответа каждые 30 минут, открытие остальных
по явному запросу оператора. Шестичасовая сверка не читает финансовые карточки,
старые сообщения или весь архив клиентов.

Состояние, позиция, срок следующей проверки и аренда задачи сохраняются в БД.
Работа не зависит от окна оператора. Изменение подключения, опубликованного
справочника или истечение аренды запрещает публикацию устаревшего ответа.

## Интерфейс

В «Подключениях» отдельно показаны новые сообщения, первичная история,
действующие клиенты и проблемы. У журнала различаются строки по счётчику CRM,
уникальные ID в базе, повторы источника, дата последнего чтения и ошибка.
Можно повторить один проблемный журнал без сброса других направлений и отдельно
запросить сверку действующих. При отсутствии свежего отчёта движение не
анимируется. Счётчики пересчитываются с кэшем, лёгкие опросы не выполняют полный
подсчёт базы. Скрытая страница прекращает опрос интерфейса; сервер продолжает
работать.

В «Профиль → Чаты → Отображение имён в списке диалогов» доступны:

1. Сначала родитель: жирная первая строка — родитель, ниже — дети.
2. Сначала ребёнок: жирная первая строка — дети, ниже — родитель.

Настройка хранится на сервере отдельно для пользователя и организации.
Переключение не меняет получателя, ID клиента, очередность, непрочитанные,
черновик или положение списка. Несколько детей выводятся в устойчивом порядке;
отсутствующее ФИО обозначается явно. Поиск продолжает учитывать обе стороны.

## Ограничения и установка

Старые записи без подтверждённого исходного ID сохраняются и показываются
отдельной проблемой. Например, ранее выявленные 283 записи нельзя объявить
сопоставленными только потому, что изменился интерфейс. Установка не удаляет их
и не запускает новый полный обход ради изменения этой цифры.

Источник предоставляет изменяемые страницы без зафиксированного снимка. Если
новая запись с новым ID появляется глубоко среди старых страниц, за уже
сохранённой границей, обычный опрос начала журнала не гарантирует её обнаружение.
Нужна отдельная адресная диагностика источника. Совпадение общего количества
строк само по себе не доказывает полноту истории.

Новых миграций схемы нет: используется существующий `outbox_events` для
подтверждений, состояния задач и личных настроек. Текущая требуемая ревизия —
`0014_ai_deepseek`. Docker Compose и хранилище сообщений не меняются.

Обычная установка из `main`:

```bash
systemctl start ramessenger-local-build.service
docker inspect --format '{{.Config.Image}}' center-messenger-api-1
```

После установки обновить страницу. Сверка продолжится на сервере; повторно
запускать полную историю или очищать БД не требуется.

## Проверка

Проверены идемпотентность и неизменность сохранённой истории, новые ответы из
CRM, архивные входящие, независимые позиции, ошибки проекции, повторяющиеся ID,
сверка только действующих, переход в архив, изоляция личных настроек и кэш
счётчиков. Проверки используют изолированный PostgreSQL-совместимый PGlite;
два теста конкурентных транзакций требуют отдельного нативного PostgreSQL.

Браузерная проверка `tests/check_incremental_sync.cjs` использует синтетические
данные и перехваченные запросы, проверяет ширину 320/390/1440, сохранение ФИО
после перезагрузки и в новой вкладке, черновик, счётчики, отсутствие ложной
анимации и параметры адресного повтора. Дополнительно проверяются состояния
монитора, роли кабинета, оформление и список из 1000 диалогов с сохранением
позиции. Доступ к рабочему VPS и его фактическое обновление этими проверками
не подтверждаются.
