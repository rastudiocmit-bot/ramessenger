# Этап 4: ошибки и возобновление загрузки карточек

Прежний загрузчик повторял итоговые 401, 403 и сетевые ошибки как одну
`crm_unavailable`. Ошибка поздней страницы начинала раздел заново. Исправление
касается финансов, недавних занятий, года занятий и связей с группами.

## Поведение при сбоях

| Причина | Действие |
|---|---|
| Подключение занято | Ожидание 5 секунд, без увеличения счётчика ошибок |
| Истёк токен API | Существующая одна попытка обновить токен |
| Итоговый 401 | Все зависимые разделы карточек этой версии подключения приостановлены до исправления ключа |
| 403 | Приостановлена операция в конкретном филиале; другие разделы и филиалы продолжаются |
| 429 | Сохранён HTTP-статус и Retry-After, включая HTTP-date; бюджет хоста тоже соблюдает паузу |
| Сеть/5xx/timeout | Пауза 30 секунд с увеличением до 30 минут; хорошие страницы сохраняются |
| Клиент отсутствует в обычных и архивных точечных выборках | Явный `not_found`, повтор через сутки |
| Неподдерживаемые данные/превышение лимита | Прежний раздел сохранён, ошибочный промежуточный снимок отброшен, повтор через 30 минут |

В карточке появляются конкретная причина, статус HTTP, операция, филиал,
CRM ID, страница и время повтора. Итоговый 401 не вызывает бесконечную анимацию
загрузки. При ожидании повтора страница продолжает показывать сохранённые данные.
Эти ошибки не завершают личную сессию оператора и не сбрасывают cookies MAX.

Ручное «Обновить» может повторно проверить ранее запрещённую операцию и
снять её ограничение после успеха. Пауза 429 и блокировка ключа не обходятся
ручными открытиями. Сохранение новых реквизитов того же аккаунта и той же CRM
повышает версию, возобновляет незавершённые задания и сохраняет хорошие факты.
Смена CRM/аккаунта сохраняет прежние правила изоляции и проверки доступа.

## Продолжение с контрольной точки

За ход выполняется не более трёх новых чтений; прежний 20-секундный бюджет
API-клиента и аренда задания остаются ограниченными. Записи принятых страниц
сохраняются в `outbox_events.payload.checkpoint`. Контекст включает раздел,
подключение, версию, опубликованный справочник, филиал, Customer ID, контакт,
ребёнка, запрос ручного обновления и исходный диапазон дат. Размер ограничен
8 МиБ на задачу; токены/ключи туда не попадают.

После рестарта сохранённые страницы воспроизводятся локально, а CRM получает
только недостающие запросы. Изменение общего количества строк, повтор ID,
ошибка разбора или неверный клиент не превращаются в полный раздел. До проверки
всех страниц оператор видит предыдущий целостный снимок. Время финансов/занятий
отражает начало чтения, а не искусственно обновляется после долгого повтора.
Более свежие целостные сведения не заменяются старым начатым чтением.

Каждая запись страницы и публикация проверяют действующего владельца, срок
аренды, версию настроек, справочник и исходную связь клиента. Просроченный
работник не может сохранить страницу или заменить карточку. Новое ручное
обновление во время чтения остаётся отдельным ожидающим проходом.

Очередь чередует финансы, недавние занятия, историю и группы. Задания без хода
более 15 минут получают приоритет; это защищает автоматические задачи при
постоянных ручных открытиях. Внешний запрос не держит транзакцию БД открытой.

## Скорость чтения и диагностика

Выбор отображаемой CRM-карточки читает только исходную семью и все её возможные
прямые связи по основному телефону вместо всего справочника. Правила проверки
семьи, конфликтующих владельцев, ручных привязок и адресата MAX сохранены.
Для `chats/bootstrap` добавлены этапы `bootstrap.context`, `bootstrap.list`,
`bootstrap.history`. Медленные этапы используют прежний префикс `Slow API read`.
В логах нет имён, ID клиентов, текстов сообщений или ключей.

Для адресной проверки на установленной новой версии:

```bash
docker exec center-messenger-api-1 /opt/venv/bin/python -m center_messenger.client_audit \
  --workspace 4f7a27e9-9b19-486d-9700-2df7784a24cb \
  --name 'Кашук Мария Васильевна'
```

Команда читает только нашу БД в транзакции READ ONLY. Она показывает все найденные
CRM ID отдельно, сохранённые связи диалогов, выбор отображаемой карточки,
количество/период сообщений, возраст кэша и причины ожидания заданий. Имена служат
фильтром поиска и не используются для объединения клиентов. Тела сообщений,
телефоны, email и реквизиты подключения не выводятся. Для фактического заключения
по этому клиенту нужен результат с VPS; тестовая карточка не является проверкой
производственных данных.

Новых миграций, сброса истории или повторного полного импорта не требуется.
Фактическое ускорение карточек и причина оставшейся задержки bootstrap проверяются
после установки на VPS. Успешный SQL-прогон не закрывает приёмку прежней HTTP 503
в «Сводке» и нагрузочную проверку всей системы.
