# Изоляция нативного MAX через AlfaCRM

В браузерном контейнере `max-worker` остаются вход, OTP, восстановление
сессии, получение истории и отправка из существующих очередей. В API
браузерные вызовы запрещены, ручной вход/OTP проходят через закрытый
контрольный канал с дополнительным ключом и повторной проверкой сессии/CSRF.
API продолжает читать чаты, карточки и обновления из общей PostgreSQL.

Worker закреплён отдельным image tag по SHA и image ID. Обычное обновление
API не пересоздаёт worker и не меняет его pin. Смена схемы не продвигается
поверх старого worker без отдельного парного плана. Никаких новых каналов,
таблиц, фоновых API телефонии или интерфейсных вкладок не добавлено.

Первое переключение допускается только по точному server-side плану через
существующий deploy owner. Сначала проверки и резервная копия, затем
readiness нового worker, переключение API и повторная проверка worker.
Откат возвращает старый Compose/окружение/API и сохраняет новые записи БД.
Незавершённое переключение восстанавливается по журналу перед следующим выпуском.

Эксплуатационная инструкция и ограничения проверки:
[MAX-контейнер](../operations/max-container.md).
Публикация кода не является подтверждением фактического перехода VPS.
