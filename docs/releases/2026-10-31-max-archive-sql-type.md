# Явный тип SQL-параметра исходной записи MAX

Выпуск `ca6f0f7` исправил JSON тестовой подготовки. Следующий обязательный
серверный PostgreSQL-набор выявил ошибку `AmbiguousParameter` в новом запросе
`native_archive_relink.counterpart`: один параметр исходного ключа использовался
одновременно внутри `IN` и полиморфной функции `concat` без явного типа.

Оба использования этого параметра теперь имеют `CAST(:source AS text)`.
Предикаты выбора, точные ID, проверки истории и запреты переноса сохранены.
Остальные новые запросы проверены: nullable UUID, время, массивы и JSON уже
имеют явные типы; другие параметры сравниваются с типизированными столбцами.
Изменение приложения ограничено одной строкой SQL. Миграций, новых зависимостей
приложения, изменений Compose и скриптов развёртывания нет.

Дополнительная локальная проверка использовала PostgreSQL 18.6 в WASM
(PGlite 0.5.13, pglite-socket 0.2.16) с SQLAlchemy/psycopg, всеми миграциями и
существующими синтетическими fixture. Три сценария `ArchiveDatabaseTests`
успешны: сохранение сообщений/failed-команд и старых ссылок, блокировка
неподтверждённой истории/unknown-отправок, аннулирование связи при смене телефона.
Простой запрос отдельно воспроизвёл ошибку неявного параметра и прошёл с cast.
Также локально прошли 163 проверки правил, тестовой подготовки, защиты,
обновления worker, диагностики и резервного копирования.
Этот временный движок не добавлен в проект и не заменяет проверки на точном
production image PostgreSQL 17.11. На VPS по-прежнему обязательны 161 offline
и 71 isolated DB-проверка, без пропусков, до замены рабочих контейнеров.

Policy обновляет только хэш проверенного `native_archive_relink.py`.
Для выпуска нужны явная установка нового поколения policy, обновление
подготовленного плана точного SHA через `max_runtime_deploy.py --update-worker`
и существующий `ramessenger-local-build.service`. Рабочие контейнеры предыдущего
выпуска остаются на месте до прохождения всех проверок.
