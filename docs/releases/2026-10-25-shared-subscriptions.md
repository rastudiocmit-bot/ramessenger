# Один абонемент в нескольких филиалах

Карточка ребёнка собирала абонементы простым объединением списков из всех
филиалов. При возврате одного CustomerTariff ID в двух филиалах появлялись две
одинаковые строки и счётчик «2». Аналогично складывался общий
Customer.paid_lesson_count. Общий денежный баланс уже учитывал Customer ID один
раз и в этой правке сохраняет свою семантику.

Сервер теперь возвращает общий список абонементов выбранного ребёнка с ключом
`(Customer ID, CustomerTariff ID)` внутри текущих организации и подключения CRM.
Повтор одного ID объединяется. Филиал для отображения определяется по реальным
занятиям ребёнка, а не по контекстам запросов или числу его филиальных карточек.
Два разных ID абонементов с одинаковым названием и тарифом остаются двумя
покупками. Один номер абонемента у разных Customer ID не объединяется.

В [документации AlfaCRM](https://alfacrm.pro/usefull/integrations/integration/api)
CustomerTariff `id` обозначает абонемент в карточке клиента, `tariff_id` — тариф
в справочнике. Для учёта покупок используется первый. У CustomerTariff также
документированы `subject_ids`, `lesson_type_ids`; у Lesson — `branch_id`,
`subject_id`, `lesson_type_id`, `group_ids`, `customer_ids`, `details`. Поле
`details.ctt_id` у конкретного клиента связывает занятие с покупкой. Разрешённые
`Tariff.branch_ids` ограничивают возможность использования, но сами по себе не
доказывают, что ребёнок занимается там по этому абонементу.

Правило связи:

1. Проверить Customer ID, реальный филиал занятия, отсутствие отмены, сроки и
   ограничения абонемента по предмету и типу занятия.
2. При наличии `ctt_id` сопоставить именно этот ID покупки. Другой ID не
   подменяется похожим названием или подходящим предметом.
3. При отсутствии `ctt_id` разрешить сопоставление по ID предмета, типу,
   разрешённому филиалу и срокам только с одной подходящей покупкой. При двух
   кандидатах не выбирать первый.
4. Подтвердить участие ребёнка по деталям урока, Customer ID или актуальному
   членству в группе этого филиала. Ссылка оплаты группы использует те же
   подтверждённые связи.

Список филиалов абонемента формируется только из таких занятий. Наблюдение
абонемента через два API-контекста при занятиях лишь во втором даёт одну строку
со вторым филиалом. Если занятий не найдено или сведения недостаточны,
отображается «Филиал по занятиям не подтверждён». Филиал из URL не подставляется.
Данные ограничены существующим окном чтения занятий: год назад и 90 дней вперёд.

Остаток оплаченных занятий считается один раз по Customer ID. Для нескольких
финансовых Customer ID одного ребёнка остатки складываются. Более свежие данные
заменяют старое наблюдение; при равносвежих противоречиях сумма остаётся
неизвестной. Для абонемента конфликт обозначается явно, без ложной второй
покупки и бесконечного состояния подготовки.

Исходные записи кэша и ссылки филиалов сохраняются. Старый кэш не содержит ID
предметов и реального филиала занятий; такие записи однократно ставятся на
обновление без ожидания 30 минут. Автоматическое обновление по-прежнему касается
семей с ожидающими ответа сообщениями, остальные обновляются при явном открытии
карточки. До получения фактов филиал не выдумывается. После обновления обычный
30-минутный интервал продолжает действовать; бесконечного обновления по признаку
«не удалось сопоставить» нет. Повторный импорт сообщений, очистка базы и миграция
не нужны. После установки обновить страницу и заново открыть карточку.
Новая версия `chat.js` — `0.11.1`.

Проверки покрывают общий абонемент двух филиалов, отдельные покупки одного
тарифа, разные Customer ID, свежесть и конфликты, сохранение связей с группами,
формирование ответа из двух уже заполненных кэшей, корректные счётчики и
неизвестные значения. `tests/check_family_subscriptions.cjs` проверяет реальную
разметку карточки при ширине 1440 и 390 на синтетических данных с полностью
перехваченными запросами. Фактические ID из рабочей карточки на VPS из среды
разработки не запрашивались; показанный пользователем случай проверяется этим
правилом совпадения ID, без удаления похожих записей по названию.
