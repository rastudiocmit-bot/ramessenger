# Приоритет открытой карточки клиента

## Причина изменения

На карточках без неотвеченных сообщений сохранённые основные сведения могли
появляться быстро, а абонементы, занятия и их связи — последовательно через
20–70 секунд. Все разделы обрабатывал один серверный исполнитель, однако каждое
задание получало своё время запроса. Более позднее задание групп или годовой
истории могло обойти данные, которые оператор видит в верхней части карточки.

Дополнительно первый запрос `cached_only` после смены активного Customer ID не
восстанавливал отсутствующую локальную проекцию. Поэтому готовые данные новой
активной карточки могли не попасть в первый ответ, хотя уже находились в
PostgreSQL.

## Новое поведение

- Один клик открытия создаёт общий ручной пакет с единым временем запроса.
- Порядок ручного пакета: баланс и абонементы, недавние занятия, группы, годовая
  история.
- Повторы и смена версии справочника сохраняют исходный ручной приоритет.
- Отсутствующая проекция Customer ID восстанавливается из локальной базы в
  `cached_only` без запроса к AlfaCRM и без постановки внешней задачи.
- Интерфейс пишет «Проверяем связь с абонементом», пока не готовы занятия,
  группы и сопоставление. «Связь не подтверждена» показывается только после
  завершения необходимых разделов.

## Ограничения нагрузки

Количество исполнителей и частота запросов AlfaCRM не увеличены. Старое фоновое
задание по-прежнему получает ход после пяти ручных проходов. Карточки диалогов,
где ответ не требуется, впервые загружаются при открытии и затем читаются с
диска; автоматическая 30-минутная подготовка остаётся для диалогов, требующих
ответа.
