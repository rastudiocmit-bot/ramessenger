# Отправка без технических уведомлений

## Правило интерфейса

Под исходящим сообщением нет пояснений о занятом браузере, очереди,
переподключении, изменении настроек или неизвестном результате. Ожидание,
отправка и сверка обозначаются часами; подтверждённая отправка — галочкой.
Это правило действует и для значка последнего сообщения в списке диалогов.
Технический код сохраняется для диагностики, но не выводится под сообщением.

Единственная ошибка: **«Сообщение не отправлено»**. Основание — доказанное
отклонение, отмена до отправки или отрицательный статус источника. Таймаут,
отсутствующая строка при одном чтении и истёкшее время не доказывают неудачу.
У неопределённой отправки нет кнопки повторной отправки. У доказанной ошибки
сохраняются «Повторить» и «Изменить», если адресат определён и отправка разрешена.

Недоступность API 5xx, сетевой сбой или таймаут опроса не создают уведомление
в переписке и не удаляют уже отображённые сообщения. Ошибки доступа и действия
в отдельных формах по-прежнему обрабатываются, а ограничение длины текста
показывается перед отправкой.

## Проверка и восстановление

1. Команда, принятая API, сохраняется в PostgreSQL с уникальным request_id.
2. При потерянном HTTP-ответе клиент сначала читает историю. Если команды там
   ещё нет, повторяет только приём той же команды тем же API с тем же UUID.
   Сервер возвращает существующую команду, не создавая новую отправку.
   Повторы ограничены увеличивающейся паузой до 60 секунд, одновременно работает
   только одно автоматическое восстановление на диалог. Новый черновик сохраняется.
3. После начала внешней отправки отсутствие подтверждения даёт unknown.
   Отправитель не повторяет POST в AlfaCRM. Вместо этого будит сохранённую
   очередь чтения журнала, не сбрасывая её курсоры, backoff и действующие аренды.
4. Существующий импорт исходящих сопоставляет текст, клиента, филиал, доступный
   peer ID и время фактической отправки. Только однозначное совпадение связывает
   записи и переводит unknown в accepted. Чужой филиал и неоднозначность не
   должны подтверждать отправку. Рабочая очередь продолжает проверяться после
   закрытия вкладки и перезапуска процесса.
5. Если CRM недоступна или совпадение не доказано, сохраняется unknown, а не
   ложная ошибка или автоматическая повторная отправка. Очередь живого чтения
   продолжает работу с существующими паузами при ошибках; архив не перезапускается.

Автоматическое восстановление потерянного запроса **до приёма API** работает,
пока открыта вкладка; принятую API команду и её последующую проверку хранит сервер.
Эта правка не меняет механизм остановки контейнера при деплое.

## Проверки

- Очередь, занятый браузер, unknown и устаревшая ошибка у accepted не дают текста.
- История подтверждает unknown без POST из браузера оператора.
- Потерянный приём восстанавливается тем же UUID, новый черновик не затирается.
- Ошибка адресата не открывает возможность слепого повтора.
- Новая копия в queued/unknown не маскирует неудачу предыдущей копии.
- Сервер сериализует только подтверждённые ошибки; unknown будит чтение,
  а не отправку. Существующие проверки нативного отправителя защищают границу POST.
