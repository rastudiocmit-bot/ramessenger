# Общий баланс AlfaCRM в карточке семьи

Раньше верхнее поле «Баланс» брало сумму остатков абонементов, поэтому деньги
на базовом счёте пропадали из показателя. Теперь используется общий остаток
`Customer.balance`, который уже включает базовый счёт и абонементы.

Правило применяется ко всем клиентам, без исключений по ФИО или конкретному ID.
Повторы одного глобального ID по филиалам не удваивают сумму. Отдельные
финансовые карточки выбранного ребёнка учитываются вместе, соседние дети
семьи сохраняют собственные показатели. Нули, задолженность, неизвестный
остаток и устаревший кеш проверены отдельно.

Обновление карточки теперь делает ограниченный read-only запрос
`/v2api/{branch}/customer/index` по точному ID, обновляет общий баланс и число
оплаченных занятий в существующем кеше. Более свежий кеш используется при
чтении карточки; более старый не перекрывает новый опубликованный справочник.
Остатки отдельных абонементов показываются как раньше. Подсказка к общему
балансу и описание задолженности приведены в соответствие с новым смыслом.

Проверки:

- 10 новых проверок API-контракта и денежного расчёта, включая пример
  2725,00 на абонементе + 1237,50 на базовом счёте = общий 3962,50,
  без повторного прибавления абонемента.
- 3 интеграционные проверки чтения из БД: справочник без кеша, приоритет
  свежих данных и независимость детей/повторов ID в филиалах.
- 2 проверки DOM: общий остаток рядом с отдельной суммой абонемента
  и отрицательный общий баланс при положительном абонементе.
- Весь серверный набор: 142 проверки, 140 пройдены, 2 существующие проверки
  нативных блокировок пропущены в PostgreSQL-совместимой среде PGlite.
  Весь интерфейсный набор: 65 проверок пройдены.
- compileall, node --check, git diff --check.

Новый прогон Chromium в этой среде недоступен: загрузчик вернул неполный архив
браузера. Вёрстка и CSS не менялись; числовое поле и подсказки проверены в DOM.
Рабочая база и активная сессия AlfaCRM недоступны из среды разработки;
фактическое текущее значение конкретного клиента проверяется после установки.

Миграции и новые зависимости отсутствуют. Схема остаётся
`0012_member_sections`; существующий защищённый установщик и резервная копия
сохраняются. Ресурс chat.js обновлён до 0.10.2.

```sh
systemctl start ramessenger-local-build.service
docker inspect --format '{{.Config.Image}}' center-messenger-api-1
```

После подтверждения нового образа обновить страницу полностью.
Правильный общий остаток появляется из имеющегося справочника для всех
карточек; кнопка обновления карточки перечитывает текущую сумму из AlfaCRM.
Повторный импорт сообщений для этой задачи не нужен.
