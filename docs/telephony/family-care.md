# Сопровождение семьи по телефонным обращениям

Этот выпуск добавляет раздел **Телефония** в левое меню. Он обрабатывает
уже сохранённые звонки и расшифровки внутри существующего
`telephony-worker`. Установка на VPS подтверждается отдельно по журналу
единственной службы выпуска и фактическим образам контейнеров.

## Проверяемые факты и предложения

Правила извлечения работают локально по существующей расшифровке. Они
не заменяют семантический разбор и могут пропустить непривычную формулировку.
Новые обращения не запускают дополнительные платные запросы ИИ или Новофона.
Задача, этап, ответственный и срок требуют подтверждения человека. Обещание
одного из говорящих нельзя автоматически приписывать администратору: каналы
ASR имеют пометку «роль не подтверждена».

Цитата хранится буквально, до 400 символов. Позиция относится к началу
размеченного фрагмента, а не к пословной отметке. Длинный исходный текст
анализируется в пределах 200 000 символов с явной отметкой ограничения;
полная сохранённая расшифровка доступна страницами по запросу.
Архив старше недели не превращается в срочные обещания перезвонить. Такие
фрагменты видны в истории и возвращаются в работу после проверки сотрудником.
Разговор после пропущенного подтверждает факт контакта, но не решённость
всех вопросов. Отменённая/закрытая задача не закрывает обращение автоматически.

Семья определяется номером в конкретном аккаунте Новофона и организации.
Скрытые номера остаются отдельными обращениями. Совпадение номера не меняет
MAX-адресата и не объединяет переписки. При нескольких контактах CRM
показываются все совпавшие названия; сотрудник проверяет связь.

Период отчёта — период **активности обращения**, а не когорта продаж.
Упоминание направления не равно намерению купить. Этапы могут пропускаться;
посещение, абонемент и продление здесь являются отметками сотрудника.
Ограничение отчёта — 5000 доступных обращений с явным сообщением; страницы
по 100. Обращение хранит последние 50 звонков/100 предложений/50 отметок,
с пометками ограничения. Полная история настоящих звонков остаётся в
`telephony_calls` и читается отдельно по 25 записей, без усечения архива.

## Размещение и доступ

- API аутентифицирует сессию и проверяет доступ к сообщениям, затем передаёт
  проверенную идентичность в закрытый `/care` контейнера телефонии. Worker
  повторно проверяет действующую сессию и членство, а не доверяет роли браузера.
- Хранение: собственные `phone-care-*-v1` темы в существующем tenant-scoped
  `outbox_events`; в очереди MAX и сообщения этот блок не пишет.
- Обработка вызывается штатным scheduler телефонии. Первичное чтение —
  страницами по 16 ID, один источник за проход; новые звонки приоритетнее архива.
- Задача и отметка обращения создаются одной транзакцией с устойчивым ID;
  устаревшая версия отклоняется. После сетевой неопределённости повтор безопасен.
- Администратор назначает работу и ведёт очереди/примеры/сводку. Оператор
  видит собственные и неназначенные обращения, а также источник своей задачи;
  источник чужого обращения не даёт права его менять. Наблюдатель не меняет
  данные. Для создания задачи нужен доступ к задачам, у исполнителя тоже.
- Запись и полный текст читаются только по действию пользователя; ссылка
  провайдера и API/SIP-пароли браузеру не возвращаются. Прослушивание аудируется.
- При смене организации/выходе очищаются частные данные и останавливается
  плеер. Старый worker возвращает явную ошибку несовместимости, не пустую очередь.

## Проверки и выпуск

Локально: 357 UI-тестов, 21 серверная проверка нового блока, реальный Chromium
на ширинах 1440/390 (задача с московским сроком в браузере America/New_York,
запуск синтетического аудио, раскрытие текста, переход к задаче, разные ID
двух очередей, отсутствие горизонтального переполнения).
Совместимый suite: 310 проверок, 299 пройдены; 11 проверок дочернего процесса
не запускаются из-за ограничений PID namespace этой среды. Chromium в локальном
прогоне подставлен только тестовым harness; зависимости приложения не менялись.
Полный обязательный suite на VPS должен пройти без пропусков.

Новые PostgreSQL/RLS/транзакционные проверки включены в обязательный
`run_max_compatibility.py --database`. Локально PostgreSQL отсутствует;
результата этих проверок пока нет. Служба выпуска выполняет их на изолированной
временной БД **до** замены рабочих контейнеров. Пропуск или ошибка блокирует выпуск.

Точный план допуска: [family-care release](../releases/2026-11-01-family-care.md).
Схема остаётся `0032_telephony_ai`; Compose, зависимости, controller, MAX worker
и его образ не обновляются этим выпуском. Обновляются API и telephony-worker.
